Один хост, Traefik на периметре, стэки в отдельных каталогах, деплой — self-hosted runner на том
же сервере. Схема рабочая, но у неё десяток мест, где правильный по документации конфиг молча
не работает. Скил — про них, а не про DevOps вообще.

## Два правила поверх всего

**Канон применяется к тому, что создаётся заново. Существующий рабочий compose или workflow не
переписываешь.** Стэки жили и деплоились до тебя, расхождение с каноном ниже — чаще история, чем
ошибка. Нашёл расхождение — соберёшь отдельным списком и покажешь человеку. Молча приводить
к канону запрещено: это и есть главный способ сломать прод из лучших побуждений.

**Старшинство источников, сверху вниз:**

| Источник | Когда |
| --- | --- |
| `CLAUDE.md` рабочей репы | всегда, если есть |
| карточка стэка `docs/projects/<stack>.md` | если работаешь в репе сервера |
| `docs/agent-deploy-guide.md` | там же; **местами отстаёт от практики** |
| этот скил | когда выше молчат |

Гайд писался раньше части изменений: в нём может не быть свежей схемы сборки, а числа лимитов
бывают старее, чем в `CLAUDE.md`. **Расхождение не решай молча — покажи человеку оба варианта.**

## Что ты делаешь и чего не делаешь

Пишешь файлы и выдаёшь человеку готовые команды. **Не выполняешь** сам: `ssh` с изменяющей
командой, `docker compose up/down/restart/exec` на проде, `rsync` на сервер, `docker system prune`,
`ufw`, `iptables`, миграции, правку в `/opt/`.

Читать можно и нужно: `docker compose ps`, `docker logs`, `git status/diff/log`,
`ssh <host> 'docker ps'` и прочее без побочных эффектов.

## Деплой: два канона, признак виден в репе

Модель по умолчанию пишет третий вариант — `docker build` + `push` в абстрактный registry и
деплой по SSH — и промахивается мимо обоих. **Сначала посмотри в репу, потом пиши.**

| Признак в репе | Канон |
| --- | --- |
| есть `build-*-image.yml` или `image: ghcr.io/...` в compose | образ собирается в CI и приезжает `docker compose pull`. `--build` на проде **не предлагать**, `docker login` в workflow оставить |
| ничего из этого нет | `rsync` исходников в каталог стэка + `docker compose up -d --build` на проде. Runner живёт на том же хосте, registry в схеме не участвует |

Сборка в CI появляется не от красоты, а чтобы снять деплой с зависимости от apt-зеркал
(см. «Debian-образы» ниже). Если стэк уже переехал на неё — обратно не тащи.

### Флаги rsync — по владельцу файлов, а не по привычке

`-a` пытается сохранить owner/group и падает с `chgrp: Operation not permitted` на файлах, чей
владелец отличается от runner-а. Отсюда правило по наблюдаемому признаку:

- в стэке есть каталоги, созданные процессом контейнера под чужим uid — `tmplc/`, `sess/`,
  `cache/`, `logs/`, `uploads/` → **`-rlptD --delete`**;
- таких каталогов нет (Node, статика, бот) → `-a`/`-av` работает, и рабочий workflow из-за
  этого флага **не переписываешь**.

### `--exclude` — принцип, а не готовый список

Исключаешь два класса:

1. **Чем runner не владеет** — runtime-каталоги контейнера (выше). `--delete` иначе споткнётся
   о права.
2. **Чего нет в git** — `.env` (без этой строки `--delete` **стирает секреты**),
   persistent-данные пользователей (альбомы, загрузки, медиа), per-stack ассеты и темы, лежащие
   только на сервере.

**Не исключаешь то, что собирается на runner-е до rsync.** У SPA `dist/` собран шагом выше и
обязан уехать — выкинешь его, и на сервер приедет пустой сайт. Готовый список — в
[references/deploy-workflow.md](references/deploy-workflow.md), но копировать его целиком в
не-PHP проект не нужно.

### `.env` кладёт человек

Один раз, по SSH, до первого прогона workflow, `chmod 600`. CI его не подкладывает и не
перезаписывает — ни через `secrets.ENV_FILE`, ни как-либо ещё. Нет `.env` к моменту
`docker compose up` — контейнеры не поднимутся на валидации переменных.
Литералов секретов в `compose`, `Dockerfile` и `environment:` не бывает.

## Traefik

**Две пары labels на сервис**: `<svc>-http` (entrypoint `web`, редирект на HTTPS) и `<svc>-https`
(entrypoint `websecure`, tls, резолвер, middlewares), плюс `loadbalancer.server.port` с портом
**внутри** контейнера. Полный шаблон — [references/compose-traefik.md](references/compose-traefik.md).

**Резолвер задавай в labels явно.** На entrypoint `websecure` уже прописан production-резолвер,
поэтому HTTPS-роутер **без** явного `tls.certresolver` молча получает production-ACME с его
жёсткими rate limits. Новый домен — сначала staging-резолвер, переключение на production после
успешной проверки. Забыл строку — первый же кривой деплой съест лимит на неделю.

**Глобальные middlewares не дублируй в labels.** Rate-limit и inFlightReq висят на обоих
entrypoint-ах и покрывают новый сайт автоматически. Повышать глобальный лимит ради одной шумной
интеграции не нужно — её IP заносится в исключения.

**`dynamic.yml` смонтирован пофайлово и read-only.** Правка, меняющая inode — `mv`, `sed -i`,
atomic save редактора — до контейнера **не доедет**, и hot-reload молча не сработает. Файл
правится только in-place (`cp`, `cat > file`). Проверяешь **не файл, а рантайм**, через API
дашборда на loopback:

```bash
docker exec traefik wget -qO- http://127.0.0.1:8082/api/http/middlewares/<name>@file
```

**Статический конфиг Traefik = рестарт = недоступность всех сайтов хоста** на несколько секунд.
Один контейнер терминирует все домены. Правка статики — только с явного согласия человека;
всё, что можно, делается динамикой и labels.

## Compose

**`ports:` не пишешь.** Внешний трафик заходит через Traefik по labels, проксируемые контейнеры
живут в его сети, базы и фоновые сервисы — только во внутренней. Отладочный доступ (дашборды,
БД) публикуется **на `127.0.0.1:`** и открывается SSH-туннелем, наружу — никогда.

Исключение по признаку: **сервис, который не ходит через HTTP-прокси** (relay, нестандартный
протокол) публикует порт явно и требует ручного `ufw allow`. Такой стэк «чинить» не надо.

**Новый сервис приходит с `mem_limit`.** Хост один и память общая; сервис без лимита утягивает
за собой соседей. (`healthcheck` ставь тоже, но за него напоминать не нужно — а вот лимит памяти
забывается почти всегда.)

**Миграции forward-only, механизм у каждого стэка свой — не унифицируй самовольно.** Встречаются
четыре: одноразовый сервис-мигратор с `condition: service_completed_successfully`; отдельный шаг
workflow вида `upgrade head`; SQL руками через клиент в контейнере; миграций нет вовсе, схемой
владеет CMS. Определяй по репе, а не по тому, что привычнее.

## Dockerfile

**Debian-образам первой строкой меняй apt-зеркало.** `deb.debian.org` за Fastly из РФ
недоступен — сборка виснет без внятной ошибки, а не падает. IPv6 на хосте выключен глобально
по той же причине; если outbound из build-стадии висит, дело обычно в этом.

```dockerfile
RUN sed -i 's|http://deb.debian.org|http://mirror.yandex.ru|g' /etc/apt/sources.list.d/debian.sources
```

Шаблоны Node / PHP-FPM / Python, порядок стадий, non-root и особенности `composer` —
в [references/dockerfile.md](references/dockerfile.md).

## Инцидент: три вещи, которые ищут не там

| Симптом | Где смотреть |
| --- | --- |
| **429 у легитимного клиента** | источников **два**: глобальный rate-limit/inFlightReq на entrypoint-ах прокси **и** собственные per-IP лимиты nginx внутри стэка. Сначала определи, чей 429, по логам контейнера сайта; потом иди в `dynamic.yml` и список исключений |
| **Нужно заблокировать IP** | только цепочка iptables `DOCKER-USER`. Docker с `iptables:true` обходит UFW `INPUT` для трафика к контейнерам — `ufw deny from <ip>` HTTP к прокси **не блокирует** |
| **Считаешь что-то по `docker logs`** | недостоверно: хост спонтанно перезагружается и обнуляет логи контейнеров. Счётчики бери из агрегатора логов, не из `docker logs \| grep -c` |

**`docker system prune --volumes` не запускай и не предлагай.** Наблюдалось удаление именованных
томов с живыми данными вопреки тому, что обещает `--help`. Штатная чистка —
`docker system prune -af --filter until=168h`, без `--volumes`.

Больше симптомов и куда по ним идти — [references/incidents.md](references/incidents.md).

## Найденное отступление не чини молча

Наткнулся в проде на `:latest`, отсутствующий healthcheck, слабую аутентификацию БД, устаревший
базовый образ — **сверься сначала с `docs/todo.md` и карточкой стэка**. Такие вещи обычно уже
описаны и оставлены осознанно, с причиной. Записи не нашёл — покажи человеку списком, но правку
не начинай: у отступления может быть цена, которой не видно из репозитория.

**Новый стэк в репе сервера — сначала карточка** по `docs/onboarding-template.md`, потом compose
и workflow. Пробелы карточки — это пробелы понимания, которые всплывут на проде.

## Чего здесь нет

Kubernetes, Helm, ArgoCD, Terraform, Pulumi, облачных провайдеров и managed-сервисов в этом парке
не существует. Не предлагай их как решение — даже когда задача выглядит как учебный пример из
доки про k8s.
