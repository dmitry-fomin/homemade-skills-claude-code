# Симптом → где смотреть

Таблица на один заход. Разборы инцидентов и постмортемы живут в доках сервера, не здесь.

| Симптом | Первое место | Что легко перепутать |
| --- | --- | --- |
| **429 у легитимного клиента** | глобальный rate-limit / inFlightReq на entrypoint-ах прокси и список исключений `sourceCriterion` | у отдельных стэков есть **собственные** per-IP лимиты в nginx, тоже отдающие 429. Сначала определи по логам контейнера сайта, чей это отказ, и только потом иди в `dynamic.yml` |
| **правка `dynamic.yml` не подхватилась** | inode: файл смонтирован пофайлово и read-only, `mv`/`sed -i`/atomic save до контейнера не доезжают | смотреть на файл на хосте бесполезно — он правильный. Проверяй рантайм: `docker exec traefik wget -qO- http://127.0.0.1:8082/api/http/middlewares/<name>@file` |
| **сертификат не выпускается / выпустился не тот** | резолвер в labels роутера | без явного `tls.certresolver` берётся резолвер с entrypoint, а он **production**. Несколько неудачных попыток выжигают недельный лимит ACME |
| **`No space left on device` на деплое** | build cache на проде, если стэк собирается на месте | `docker system prune -af --filter until=168h`. **Без `--volumes`** — наблюдалось удаление именованных томов с живыми данными вопреки `--help` |
| **`rsync` падает: `chgrp: Operation not permitted`** | флаг `-a` на стэке с каталогами под чужим uid | лечится `-rlptD`, а не `sudo` и не сменой владельца на хосте |
| **`--delete` снёс контент или секреты** | отсутствующий `--exclude` для `.env` или persistent-каталога | восстановление — из бэкапа; сначала проверь, что в exclude-списке, потом деплой |
| **контейнеры не поднялись после первого деплоя** | нет `.env` в каталоге стэка | compose падает на валидации переменных. `.env` кладёт человек по SSH, CI его не подкладывает |
| **workflow зелёный, сайт лежит** | нет шага Verify | `up -d` успешен, даже если контейнер сразу ушёл в рестарт-петлю |
| **блокировка IP через `ufw` не работает** | цепочка iptables `DOCKER-USER` | Docker с `iptables:true` обходит UFW `INPUT` для трафика к контейнерам. Блокировка — только в `DOCKER-USER` |
| **счётчики по `docker logs` не сходятся** | хост спонтанно перезагружается и обнуляет логи контейнеров | статистику бери из агрегатора логов, не из `docker logs \| grep -c` |
| **сайт недоступен несколько секунд после правки Traefik** | это рестарт контейнера прокси | один контейнер терминирует все домены хоста. Статический конфиг правится только с согласия человека |
| **фоновая задача «работает», но результата нет** | cron-задачи и обработчики логов умирают тихо | падение раз в неделю не видно никому: у задачи должен быть наблюдаемый выхлоп, иначе поломка живёт месяцами |

## Правило разбора

Прежде чем чинить — **определи источник отказа**, а не первый правдоподобный. Половина строк
выше существует потому, что симптом одинаковый, а мест как минимум два: 429 из прокси или из
стэка, редирект от Traefik или от приложения, лимит на entrypoint или в labels.

Изменения на проде — через человека. Твоя часть заканчивается на «вот источник, вот команда,
вот чем проверить».
