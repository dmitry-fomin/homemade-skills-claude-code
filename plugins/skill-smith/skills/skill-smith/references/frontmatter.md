# SKILL.md frontmatter — полный контракт

Источник: https://code.claude.com/docs/en/skills (раздел *Frontmatter reference*),
сверено 2026-09-12 на Claude Code 2.1.269.
Портируемое подмножество: https://agentskills.io/specification.
**Перед правкой этого файла перечитай первоисточник — поля добавляются.**

## Поля (Claude Code)

Все поля опциональны. Рекомендуется как минимум `description`.
Булевы значения принимают `true/false/yes/no/on/off/1/0` в любом регистре (с v2.1.218).
Frontmatter читается **только если открывающий `---` — первая строка файла**; иначе весь файл,
включая маркеры `---`, считается телом скила.

| Поле | Что делает | Подводные камни |
| --- | --- | --- |
| `name` | Отображаемое имя в листингах. По умолчанию — имя каталога. | **Для personal/project скилов имя команды берётся из каталога, а не из `name`.** `name` меняет команду только у plugin-скилов (`/plugin:name`). С v2.1.246 `name`, уже начинающийся с префикса плагина, не удваивается; в 2.1.216–2.1.245 удваивался. |
| `description` | Когда применять скил. Модель матчит запрос по этому тексту. Если пусто — берётся первый абзац тела. | `description` + `when_to_use` обрезаются на **1536 символов** в листинге. Ключевой кейс — первым. |
| `when_to_use` | Доп. триггеры, фразы-примеры. Приклеивается к `description`. | Считается в тот же лимит 1536. |
| `argument-hint` | Подсказка в автокомплите: `[issue-number]`, `[file] [format]`. | Значение с `[...]` **обязательно в кавычках**, иначе YAML читает его как flow-массив и весь frontmatter падает. |
| `arguments` | Имена позиционных аргументов для подстановки `$name`. Строка через пробел или YAML-список. | Порядок = позиции. Необъявленное имя не подставляется. |
| `disable-model-invocation` | `true` — скил вызывает только человек через `/name`. | Обязателен для всего с побочными эффектами (commit, deploy, отправка сообщений). Убирает `description` из контекста (тело грузится при твоём вызове) и запрещает preload в сабагенты. С v2.1.196 не даёт скилу сработать и как промпту scheduled task. Попытку модели харнесс блокирует и велит не воспроизводить шаги обходным путём. |
| `user-invocable` | `false` — скрыть из меню `/`, вызывает только модель. | Не влияет на доступ через Skill tool — для запрета нужен `disable-model-invocation`. |
| `allowed-tools` | Преавторизация инструментов **на один ход**, в котором вызван скил. Строка через пробел/запятую или список. | Грант сбрасывается на следующем сообщении пользователя, повторный вызов выдаёт его заново. Не ограничивает пул инструментов. **Workspace trust это поле не гейтит**: `allowed-tools` проектного скила применяется даже в `-p`-прогоне в никогда не доверенной папке — скил из репозитория может выдать себе широкий доступ, читай это поле перед запуском Claude Code в чужом репе. |
| `disallowed-tools` | Убирает инструменты из пула, пока скил активен. | Тоже до следующего сообщения. Не может убрать `EndConversation`, пока остаются другие инструменты. |
| `model` | Модель на остаток текущего хода. Значения как у `/model`, либо `inherit`. | С `context: fork` задаёт модель форкнутого сабагента. В настройки не пишется, сессионная модель возвращается на следующем твоём сообщении. Значение вне `availableModels` организации игнорируется — сессия остаётся на своей модели. То же в **auto mode** и в plan mode, пока классификатор проверяет команды: модель, которую auto mode не поддерживает, не применяется. |
| `effort` | `low` / `medium` / `high` / `xhigh` / `max`. Перебивает effort сессии, по умолчанию наследует. | Доступность уровней зависит от модели. `/tasks` показывает уровень на строке сабагента, если effort задан его определением или форкнувшим скилом (v2.1.242+). |
| `context` | `fork` — выполнить в изолированном сабагенте, тело скила становится промптом. | Единственное документированное значение. Без явной задачи в теле форк бесполезен. **Это не форк беседы**: истории сабагент не видит, инструкции должны быть самодостаточны. |
| `agent` | Тип сабагента для `context: fork`: `Explore`, `Plan`, `general-purpose` или кастомный из `.claude/agents/`. | Работает только вместе с `context: fork`. По умолчанию `general-purpose`. |
| `background` | Только с `context: fork`. `false` — ждать результат в этом же ходу (v2.1.218+). | По умолчанию `true` → фон + **урезанный набор инструментов** фоновых сабагентов; правки фонового форка не откатываются через `/rewind`. Харнесс всё равно ждёт результат: в `-p`/Agent SDK, при `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, при повторном вызове того же скила, пока прошлый ещё бежит, и когда скил запущен как промпт scheduled task. |
| `hooks` | Хуки на время жизни скила — регистрируются при вызове и **работают до конца сессии**, а не только в ходу вызова. Формат — см. docs/en/hooks «Hooks in skills and agents». | Снять после первого успешного срабатывания — `once: true`. Trust-диалог эти хуки **не** гейтит (в отличие от хуков во frontmatter субагента). |
| `paths` | Glob-паттерны: автозагрузка скила только при работе с этими файлами. Строка через запятую или YAML-список, формат как у path-specific rules в memory. | Гейтит только автовызов; с `disable-model-invocation: true` бессмысленно. |
| `shell` | `bash` (по умолчанию) или `powershell` — для `` !`cmd` `` инъекций и блоков ` ```! `. | `powershell` работает, только когда включён PowerShell tool: сам собой на Windows без Git Bash и с Git Bash для claude.ai/Console-аккаунтов; на macOS/Linux/WSL и в Bedrock/GCP/Foundry нужен `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`. |
| `metadata` | Свободная YAML-карта для своих данных. | Claude Code её не интерпретирует; не-карта отбрасывается. Не переиспользуй имена системных полей как ключи. |
| `license` | Из спеки Agent Skills. | Claude Code принимает, но не использует. |
| `compatibility` | Требования к среде, строка **до 500 символов**. Из спеки. | Claude Code принимает, но не использует. |

## Портируемость

| Куда отдаём | Разрешённые поля |
| --- | --- |
| Claude Code (personal / project / plugin) | все из таблицы выше |
| Загрузка на claude.ai, Skills API, `package_skill.py` из anthropics/skills | только `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` |

Расхождения спеки (agentskills.io) с Claude Code по общим полям:

| | Спека Agent Skills | Claude Code |
| --- | --- | --- |
| `name` | **обязателен**, 1–64 символа, только `a-z0-9` и одиночные дефисы (не в начале/конце, без `--`), **должен совпадать с именем каталога** | опционален, это лишь ярлык; имя команды берётся из каталога (кроме plugin-скилов) |
| `description` | **обязателен**, жёсткий лимит **1024** символа | опционален; урезается только запись листинга, на 1536 вместе с `when_to_use` |
| `allowed-tools` | строка через пробел, помечено экспериментальным | строка через пробел/запятую или YAML-список; грант действует один ход |
| `metadata` | карта строка→строка | любая карта; не-карта отбрасывается |
| путь | `.agents/skills/<имя>/SKILL.md` (VS Code, Codex) | `~/.claude/skills/`, `.claude/skills/`, `<plugin>/skills/` |

Поля `version` в спеке **нет** — версию кладут внутрь `metadata`.
Пишешь скил на вырост в claude.ai/Codex — держись шести полей и лимита 1024.

Лишнее поле при упаковке/загрузке — **жёсткая ошибка**, не игнор:
`Unexpected key(s) in SKILL.md frontmatter: argument-hint. Allowed properties are: allowed-tools,
compatibility, description, license, metadata, name`

Тело-фичи Claude Code (инъекции `` !`cmd` ``, подстановки аргументов) в claude.ai-чате и через
Skills API не работают вовсе — даже если frontmatter формально портируемый.

Скилы, включённые для аккаунта claude.ai, доступны в Cowork и cloud-сессиях; личный
`~/.claude/skills/` там не читается. Значит, скил, который должен работать в routines/cloud,
пишем в портируемом подмножестве и кладём либо в аккаунт, либо в репозиторный `.claude/skills/`.
Проверка: `validate_skill.py --portable <путь>`.

## Где живут скилы и кто кого перекрывает

| Уровень | Путь | Область |
| --- | --- | --- |
| Enterprise | managed settings | вся организация |
| Personal | `~/.claude/skills/<name>/SKILL.md` | все проекты |
| Project | `.claude/skills/<name>/SKILL.md` | этот проект |
| Plugin | `<plugin>/skills/<name>/SKILL.md` → `/plugin:name` | где плагин включён |

- Приоритет: enterprise > personal > project; любой из них перекрывает bundled-скил
  (свой `.claude/skills/code-review/` заменит встроенный `/code-review`).
- Скил перекрывает одноимённый файл в `.claude/commands/`.
- Plugin-скилы живут в своём неймспейсе и не конфликтуют.
- Project-скилы подхватываются из `.claude/skills/` рабочего каталога **и всех родительских** до корня репозитория.
- Вложенные `.claude/skills/` ниже рабочего каталога грузятся лениво — при первом чтении/правке файла в этом подкаталоге; в конфликте получают имя `apps/web:deploy`.
- `--add-dir` / `/add-dir` подгружают `.claude/skills/` добавленного каталога (исключение из общего правила: остальной `.claude/` оттуда не читается). Настройка `permissions.additionalDirectories` скилы **не** грузит.
- Имя каталога `synced` зарезервировано под скилы из claude.ai.
- Live-reload: изменения `SKILL.md` подхватываются без рестарта. Новый **корневой** каталог скилов требует рестарта; `hooks/`, `.mcp.json`, `agents/` внутри skills-dir-плагина — `/reload-plugins`.

## Подстановки в теле

| Плейсхолдер | Значение |
| --- | --- |
| `$ARGUMENTS` | вся строка аргументов; если плейсхолдера нет — аргументы дописываются в конец как `ARGUMENTS: <value>` |
| `$ARGUMENTS[N]` / `$N` | аргумент по индексу с нуля; shell-подобное квотирование (`/s "hello world" x` → `$0`=`hello world`) |
| `$name` | именованный аргумент из `arguments:`; без значения → пустая строка (индексный без значения остаётся как есть) |
| `${CLAUDE_SKILL_DIR}` | каталог самого SKILL.md — единственный надёжный способ сослаться на bundled-скрипт |
| `${CLAUDE_PROJECT_DIR}` | корень проекта (v2.1.196+) |
| `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}` | id сессии, текущий уровень effort |
| `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}` | только в plugin-скилах: корень плагина и его persistent-каталог |

`${CLAUDE_SKILL_DIR}` / `${CLAUDE_PROJECT_DIR}` подставляются и в теле, и в Bash-правилах
`allowed-tools` — на этом строится запуск bundled-скрипта без запроса прав:

```yaml
---
name: render-chart
description: Render a chart from a CSV file
allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)
---
Run `${CLAUDE_SKILL_DIR}/scripts/render.sh <csv-file>` to render the chart.
```

Литеральный `$` перед цифрой или именем аргумента экранируется бэкслешем: `\$1.00`.

## Инъекция вывода команд

`` !`command` `` выполняется **до** отправки тела модели; вывод подставляется вместо плейсхолдера.
Многострочный вариант — блок, открытый ` ```! `.

Жёсткие правила:
- `!` распознаётся только в начале строки или сразу после пробела (`KEY=!\`cmd\`` не сработает).
- Ненулевой код возврата **отменяет весь вызов скила** — модель не увидит вообще ничего.
  Добавляй `|| true`. Исключение: exit 1 у search/compare-команд считается нормой, exit ≥2 — нет.
- Инъекции никогда не спрашивают разрешение: любой ask/deny-вердикт = отмена вызова.
  Нужную команду преавторизуй через `allowed-tools`.
- Таймаут — 2 минуты (как у Bash tool), stderr сливается в stdout, большой вывод приезжает файлом.
- Подстановка одноходовая: вывод команды не пересканируется на новые плейсхолдеры.
- Отключается глобально настройкой `"disableSkillShellExecution": true`.

## Жизненный цикл контента

- Вызванный скил входит в контекст **одним сообщением и остаётся до конца сессии**.
  Пиши стоячие инструкции, а не одноразовые шаги: файл повторно не перечитывается.
- Повторный вызов с идентичным отрендеренным телом → короткая пометка «уже загружен», не копия.
- Автокомпакт возвращает после саммари последний вызов каждого скила: первые 5000 токенов каждого,
  общий бюджет 25 000, начиная с самых свежих. Большой скил после компакта имеет смысл вызвать заново.

## Бюджет листинга описаний

Листинг имён+описаний всегда содержит все имена, но описания урезаются под бюджет
(1% контекстного окна). При переполнении первыми теряют описание редко вызываемые скилы.
- Диагностика: `/doctor`, строка Skills в `/context`, `--debug`.
- Ручки: `skillListingBudgetFraction` (напр. `0.02`), `SLASH_COMMAND_TOOL_CHAR_BUDGET`,
  `skillListingMaxDescChars`, `skillOverrides: {"<skill>": "name-only"}`.

## Видимость через настройки

`skillOverrides` в `.claude/settings.local.json` (пишется из меню `/skills`: `Space` — цикл, `Enter` — сохранить):

| Значение | Видит модель | В меню `/` |
| --- | --- | --- |
| `"on"` (по умолчанию) | имя + описание | да |
| `"name-only"` | только имя | да |
| `"user-invocable-only"` | скрыт | да |
| `"off"` | скрыт | скрыт |

На plugin-скилы не действует — там `/plugin`.

## Ограничение доступа модели к скилам

Через permissions: `Skill` в deny — выключить все; `Skill(commit)` — точное совпадение;
`Skill(review-pr *)` — префикс с любыми аргументами.
