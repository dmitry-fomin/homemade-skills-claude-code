Скил — это труба до модели: «промпт → PNG на диске» и обтравка готового файла. Картинки получаются
не из-за трубы, а из-за промпта и постобработки, поэтому половина ценности здесь — в предупреждениях ниже
и в [references/prompting.md](references/prompting.md).

Скил **не** делает: композицию атласов, ресайз, упаковку в WebP, ключевание по цвету, оценку качества.
Это снаружи — `magick`, `cwebp`, свои скрипты.

## Точка входа

```bash
uv run ~/.claude/skills/image-gen/scripts/generate_image.py <подкоманда> [флаги]
```

Путь пишем ровно так — он зафиксирован в проектных документах. `uv run` обязателен: зависимости
объявлены инлайн (PEP 723), в системном python3 их нет. `uv run --with rembg` не используем никогда —
он тянет зависимости минут десять на каждый вызов.

Ключ берётся из окружения (`OPENROUTER_API_KEY`, объявлен в `~/.zshenv`). Нет ключа — скил падает
с кодом 2, не сделав ни одного сетевого запроса. Ключ не печатается никуда.

## Промпт пишем по-английски

Модель держит английский точнее: на русском промпте она чаще теряет ограничения композиции и
дорисовывает лишнее. В нейросеть уходит английский текст — **всегда**, независимо от языка разговора.
Если человек описал сцену по-русски, ты переводишь описание на английский сам и уже перевод кладёшь
в `--prompt`/`--prompt-file`. Комментарии, решения и разбор результата — по-русски.

## `generate`

| Флаг | Значение |
| --- | --- |
| `--prompt TEXT` | текст промпта (по-английски) |
| `--prompt-file PATH` | промпт файлом — кавычки не съедаются shell'ом; для длинных промптов только так |
| `--out PATH` | куда положить PNG; каталоги создаются, существующий файл перезаписывается молча |
| `--size WxH` | `1024x1024` (умолчание), `1024x1536`, `1536x1024`, `auto`; значение вне списка — код 2 |
| `--reference PATH` | референсный кадр, флаг повторяемый |
| `--seed` | `bytedance-seed/seedream-5-0-pro` — умолчание, держит референс |
| `--gpt` | `gpt-image-2` — референс не держит |
| `--qwen` | `qwen/qwen-image-3-pro` |
| `--no-fallback` | запретить подмену движка |
| `--transparent` | прогнать результат через `rembg` перед записью |
| `--n K` | K кадров за вызов, суффиксы `-1..-K` |
| `--dry-run` | напечатать собранный запрос и модель, в API не ходить |

Флаги движка взаимоисключающие. Движки, их слаги и порядок фолбэка лежат таблицей в
`scripts/engines.conf` — смена модели это правка одной строки там, скрипт трогать не нужно.
`IMAGE_GEN_MODEL=<slug>` переопределяет слаг на один запуск.

В stdout — **один JSON и ничего кроме него**; прогресс, предупреждения и ошибки в stderr.

```json
{"path":"assets/gen/pan.png","model":"bytedance-seed/seedream-5-0-pro",
 "requested_model":"bytedance-seed/seedream-5-0-pro","fallback":false,
 "size":"1024x1536","reference_used":true,"transparent":false}
```

Коды возврата: `0` — файл записан; `1` — ошибка API или фолбэк запрещён флагом; `2` — ошибка аргументов
или окружения. Рядом с `--out` копится журнал `.image-gen.log`: модель, размер, референсы, хэш промпта —
по нему через месяц видно, чем нарисован файл.

## `remove-bg`

```bash
uv run ~/.claude/skills/image-gen/scripts/generate_image.py remove-bg --in SRC --out DST
```

Флаги именно `--in`/`--out`. Подкоманда полезна и сама по себе, и как готовое окружение с `rembg`:
маски кладут рядом с исходником как `<имя>.rembg.png` и дальше ведут в свой матинг.

## Четыре предупреждения, каждое куплено браком

1. **`--no-fallback` во всех сериях, где кадры должны быть одной манеры.** По умолчанию при
   недоступности модели скил уходит на другую и продолжает работу; подмена видна полем `fallback: true`
   и строкой в stderr. Но лист, нарисованный другой моделью, — другой кот и другая бумага, якорь ломается
   тихо. Хуже: фолбэк уводит на движок, который референса не видит, — то есть на персонажа, эталона
   не видевшего. В приёмке серий стоит `fallback: false`.
2. **`--transparent` не использовать там, где нужен мягкий край.** `rembg` даёт бинарную обтравку
   keep/discard по каждому пикселю: резкий край «как у наклейки», белая бахрома, выеденные светлые
   участки внутри силуэта. Его выход годится только как жёсткая внутренность, вокруг которой альфа
   добирается матингом (см. справочник, раздел «Край»).
3. **`--reference` не работает на `--gpt`.** Движок его не держит: скил не отправляет референс, пишет
   предупреждение в stderr и ставит `reference_used: false`. Схема «эталонный кадр → референс в каждый
   лист» живёт только на `--seed`.
4. **Заказанный в промпте цвет фона приходит не тем.** Замер по seedream: заказан `#FF00FF`, получен
   `srgb(205,29,153)`, и не плашкой, а с градиентом по кадру. Цвет в промпте — это цель, а не обещание,
   что такой пиксель есть в файле. Цвет подложки для постобработки берём **с самой картинки**
   (медиана по рамке), а не из константы промпта.

## Прежде чем генерировать серию

Открой [references/prompting.md](references/prompting.md) — там приёмы, купленные браком на реальных
партиях: композиция ставится выше стиля и дублируется трижды; промпт собирается из блоков-файлов;
character-lock не существует, поэтому рисуем листом на 6–8 поз; сетку с модели снимаем полностью;
фон под вырезку выбирается замером, а не на глаз; числовые критерии приёмки края и фона.
Без него следующая партия повторит те же ошибки.

## Типичные ошибки

| Симптом | Причина и что делать |
| --- | --- |
| `error: нет ключа: переменная OPENROUTER_API_KEY не задана` | ключ живёт в `~/.zshenv`; открыть новую сессию или экспортировать переменную |
| stdout не парсится через `jq` | в stdout попало лишнее — значит, что-то печатается мимо скила; сам скил пишет туда только JSON |
| половина промпта потерялась | кавычки съел shell — перейти на `--prompt-file` |
| кадр вышел в чужой манере | `fallback: true` в JSON: сработала подмена движка, перегенерировать с `--no-fallback` |
| `--reference` будто не влияет | движок `--gpt` референс не держит; взять `--seed` |
| первый запуск идёт минуты | uv собирает окружение с `rembg`/`onnxruntime`; дальше берётся из кэша |
