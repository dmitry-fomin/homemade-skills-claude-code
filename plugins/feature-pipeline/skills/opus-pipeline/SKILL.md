# Очередь на Opus

Основной контекст здесь — **оркестратор**: берёт задачи из трекера, по одной отдаёт их
исполнителю, носит его вопросы автору и ответы обратно, ведёт журнал, закрывает задачи и пушит.
Кода не пишет, задач не читает, не коммитит. Этапов ТЗ, критики и приёмки здесь нет: исполнитель
на Opus сам пишет и сам коммитит, поэтому единственная проверка оркестратора — механическая
(коммит один, дерево чистое).

Субагенты **не могут спросить автора сами**: `AskUserQuestion` у них нет. Вопрос исполнителя —
это его остановка с отчётом, а спрашивает автора и возобновляет исполнителя ответом ты. Ради
этого оркестратор и живёт в основном контексте.

Скил вызывается только вручную — `/feature-pipeline:opus-pipeline`. Все команды — из корня
репозитория.

## Исполнитель

| Effort | Субагент |
| --- | --- |
| `medium` | `feature-pipeline:pipeline-opus-medium` |
| `high` | `feature-pipeline:pipeline-opus-high` |

Агентов два, потому что effort у субагента задаётся только в его определении: инструмент `Agent`
его не принимает, а без поля субагент наследовал бы уровень сессии. Отсюда правила вызова:
параметр `model` не передаёшь (он перебьёт закреплённую модель), тип `fork` не используешь (он
тащит весь твой контекст и игнорирует и модель, и effort). Первая строка отчёта — `готово <hash7>`,
`вопрос` или `не смог`; формат отчёта агент знает сам, в задаче его не дублируй.

## Жёсткие правила

- **Код и коммит — исполнителя.** В основном контексте не появляется ни строки кода и ни одного
  `git commit`. Твои записи в git — только `git push` в конце очереди.
- **Не читай текст задач, диффы и код.** Текст задачи исполнитель получает командой `show` и читает
  сам. В сессии живут только короткие выводы: `tracker.list`, `git status --short`,
  `git log --oneline <база>..HEAD`, отчёты исполнителя и свой журнал.
- **Вопрос исполнителя идёт автору дословно, ответ автора — исполнителю дословно.** Ты не
  отвечаешь за автора, даже когда ответ кажется очевидным.
- **В дереве одна задача за раз.** Следующая начинается после проверенного коммита предыдущей:
  исполнители делят индекс, lock-файлы и вывод генераторов, и два одновременных затрут друг друга.
- **Дерево не перекладываешь.** `git stash`, `git checkout <файл>`, `git reset`, `git clean` здесь
  не встречаются: чужую работу проще всего уничтожить именно «по дороге к задаче».
- **Трекер меняешь только `close`** и только после проверенного коммита.

## Шаг 0 — трекер, журнал, дерево, очередь

**Трекер.** `.claude/feature-pipeline.yaml`, секция `opus.tracker`: `list` — очередь по строке
`<id> <заголовок>`, `show` — текст задачи `{id}`, `close` — закрыть `{id}` (пусто — не закрывать).
Файла или `list`/`show` нет — спроси автора команды одним вопросом и предложи записать их в конфиг;
без `show` исполнителю нечего читать, и очередь не начинается.

**Журнал** живёт в git-каталоге — туда не смотрят ни `git status`, ни `git add`, и исполнитель его
не закоммитит. Файл один на очередь, имя по времени её старта — `opus-<ГГГГ-ММ-ДД>-<ЧЧММ>.journal.md`:
очередь может идти несколько дней, и имя не должно меняться посреди неё. Состояние шелла между
вызовами не живёт, поэтому каталог получаешь в каждом вызове заново:

```
D="$(git rev-parse --absolute-git-dir)/feature-pipeline"; mkdir -p "$D"; echo "$D"; ls -t "$D" | grep '^opus-.*\.journal\.md$' | head -1
```

Путь журнала запоминаешь **абсолютным** и дальше пишешь в команды буквально. Строки дописываешь
в момент события: `cat >> '<путь журнала>' <<'EOF'` … `EOF` — маркер в кавычках, чтобы `$` и кавычки
из ответов автора не раскрылись.

Журнала нет или последняя его строка — `очередь: закрыта …` — заводишь новый. Последняя строка
другая — очередь не закрыта: прочитай журнал целиком и восстанови закрытые и пропущенные задачи,
текущую, её базу, счётчик `M`, effort, вопросы и ответы автора. Последняя строка
`очередь: остановлена на <id>` — спроси автора: продолжить с этой задачи или начать новую очередь;
новую — старую закрой строкой `очередь: закрыта — брошена автором`. Это твоя память, после `/clear`
другой нет.

**Дерево.** `git status --short` пуст — дальше. Не пуст, а в журнале незакрытая задача — это своя
работа, прерванная `/clear`: продолжай её (см. «После `/clear`»). Не пуст, а журнал молчит —
**стоп и вопрос автору**: исполнитель откажется работать поверх чужих правок. Варианты — автор
коммитит своё или убирает сам; сам ты ничего не прячешь.

**Очередь и effort.** Разбери `$ARGUMENTS`: слова `medium` и `high` — effort, всё остальное — id
задач в названном порядке. Id не названы — выполни `list` (первое слово строки — id); вывод длиннее
30 строк — `| head -30` и одна строка автору, что показаны первые 30. Затем **один** вызов
`AskUserQuestion` с тем, чего в аргументах не было:

1. очередь, если id не названы, — «все по порядку» или «только первая»; свой набор автор впишет в «Other»;
2. effort, если не назван, — `medium` (обычные задачи, дешевле) или `high` (неочевидные, с проектированием).

Названо и то и другое — не спрашиваешь. В журнал: `очередь: <id id …>, effort <уровень>`.

## Цикл по задаче

1. `B=$(git rev-parse --short HEAD)`; в журнал `задача <id>: старт, база <B>, effort <уровень>`.
2. `Agent` с `subagent_type` из таблицы исполнителя. Задача — три строки: id задачи; команда
   `show` с подставленным id, буквально; «прочитай задачу этой командой и выполни». Больше ничего:
   своих пересказов задачи у тебя нет и быть не должно.
3. Жди уведомления. Исполнитель бежит в фоне и приходит сам — не опрашивай и не запускай следующую
   задачу.
4. Разбери первую строку отчёта.

### `готово <hash7>`

Проверка — две команды, обе с коротким выводом:

```
git log --oneline <B>..HEAD
git status --short
```

| Что увидел | Что делать |
| --- | --- |
| ровно один коммит, его хеш совпал с отчётом, дерево пусто | `close` с id (если задан), в журнал `задача <id>: готово (коммит <hash7>)`; раздел «открытые вопросы и расхождения» из отчёта, если не пуст, — автору одной репликой; `M = 0`, следующая задача |
| коммитов ноль, больше одного или хеш другой | **стоп**: в журнал `задача <id>: стоп — <что показал git log>`, вопрос автору; сам историю не правишь |
| коммит верный, дерево не пусто | **стоп**: в журнал `задача <id>: стоп — дерево не пусто после коммита`, вопрос автору с `git status --short` и разделом «осталось в дереве» из отчёта |

После стопа автор отвечает, что поправил сам, — повтори обе команды и иди по таблице заново, хеш
теперь сверяешь с `git log`. Пройти стоп с грязным деревом нельзя: следующий исполнитель откажется
работать поверх чужих правок. Автор хочет задачу переделать — это ветка `не смог` со словами автора
вместо формулировки исполнителя.

`close` упал — строка `задача <id>: close не прошёл — <ошибка одной строкой>` и дальше по очереди:
коммит уже есть, закрыть задачу автор сможет сам по итоговой сводке.

### `вопрос`

1. В журнал `задача <id>: вопрос —` и вопросы исполнителя **дословно**, с вариантами: после
   `/clear` новый исполнитель получит их отсюда, а ответ «второй вариант» без вопроса не к чему привязать.
2. `AskUserQuestion`: вопрос — как сформулировал исполнитель, варианты — его, помеченный
   «предпочитаю» первым с пометкой «(предпочитает агент)». До четырёх вопросов в вызове, больше — в двух.
3. Ответы — **тому же исполнителю** через `SendMessage`, адрес — agent id из результата запуска:
   завершённый субагент возобновится с полным контекстом и своим effort. В журнал
   `задача <id>: ответ автора —` и ответ дословно.
4. Жди уведомления, дальше — снова разбор первой строки.

«Реши сам» — тоже ответ, передаётся дословно.

### `не смог`

`M+1`, в журнал `задача <id>: не смог <M>/2 — <его формулировка одной строкой>`.

- **`M = 1`** — `AskUserQuestion` автору с формулировкой исполнителя дословно и вариантами:
  повтор на том же effort; повтор на `high` (только если шёл `medium`); пропустить задачу
  (только если `git status --short` пуст — иначе следующая задача начнётся на недоделанной правке);
  остановить очередь. Повтор — **новый** исполнитель: у прежнего в контексте лежит защита своего
  подхода. В его задаче к трём строкам добавь «правки предыдущего захода уже в дереве» и его
  формулировку неудачи дословно. Смена effort — строкой в журнал и только для этой задачи.
- **`M = 2`** — очередь стоит: `задача <id>: остановлено — не смог ×2`, доклад автору. Дерево не
  трогаешь, решение принимает автор.

Пропуск — `задача <id>: пропущена — решил автор`, `M = 0`, следующая задача.

## После `/clear`

Agent id живёт только в этом разговоре: возобновлять после `/clear` некого. Незакрытую задачу
из журнала сперва сверяешь с историей — `/clear` мог прийти между коммитом исполнителя и твоей
строкой `готово`:

| `git log --oneline <база>..HEAD` | Что делать |
| --- | --- |
| один коммит | таблица ветки `готово`, хеш — из `git log` |
| больше одного | стоп и вопрос автору |
| пусто, последняя строка задачи — `стоп` | вопрос автору заново, с этой строкой |
| пусто | **новый** исполнитель: к трём строкам — «правки предыдущего захода уже в дереве», если `git status --short` не пуст, и вопросы с ответами автора из журнала дословно |

Задача со строкой `готово` не переделывается.

## Конец очереди

Задачи кончились или очередь остановлена — сводка автору: закрыто N (id и хеши), пропущено,
на чём стоит, какие `close` не прошли. Есть хоть один новый коммит — `git push`; отказ (нет
upstream, расхождение с remote) — строка автору, без `--force` и без `pull`. В журнал одна из:
`очередь: закрыта, <N> готово, запушено`, `очередь: закрыта, <N> готово, пуш не прошёл — <причина>`,
`очередь: остановлена на <id>`.

## Журнал

| Событие | Строка |
| --- | --- |
| очередь взята | `очередь: <id id …>, effort <уровень>` |
| старт задачи | `задача <id>: старт, база <sha7>, effort <уровень>` |
| вопрос / ответ | `задача <id>: вопрос — <дословно>` / `задача <id>: ответ автора — <дословно>` |
| не смог | `задача <id>: не смог <M>/2 — <формулировка>` |
| смена effort | `задача <id>: повтор на high — решил автор` |
| проверка коммита не прошла | `задача <id>: стоп — <что увидел>` |
| готово | `задача <id>: готово (коммит <hash7>)` |
| close не прошёл | `задача <id>: close не прошёл — <ошибка>` |
| пропуск / остановка | `задача <id>: пропущена — решил автор` / `задача <id>: остановлено — <почему>` |
| конец | `очередь: закрыта, <N> готово, запушено` / `… пуш не прошёл — <причина>` / `очередь: остановлена на <id>` |

## Грабли

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Исполнитель работает на модели или effort сессии | в вызов передан `model` или взят `fork` | `subagent_type` из таблицы, без `model` |
| Ответил на вопрос исполнителя сам | показалось очевидным | автор отвечает на всё; ответ передаётся дословно |
| `cat >> "$J"` пишет в никуда | переменная задана в прошлом вызове Bash | путь журнала буквально в каждой команде |
| `SendMessage` вернул отказ | agent id из прошлого разговора | новый исполнитель: вопросы и ответы из журнала дословно и строка «правки предыдущего захода уже в дереве» |
| Исполнитель сразу вернул `не смог` про грязное дерево | повтор запущен без строки «правки предыдущего захода уже в дереве» | добавить строку в задачу |
| Хеш в отчёте не совпал с `git log` | исполнитель сделал два коммита или не закоммитил | стоп и вопрос автору, историю не правишь |
| После `готово` в дереве артефакты тестов | их нет в `.gitignore` | стоп и вопрос автору; убирать или игнорировать решает он |
| В трекере задача закрыта, а коммита нет | `close` вызван до проверки | `close` только после строки таблицы «ровно один коммит, дерево пусто» |
| Основной контекст распух | прочитан текст задачи или дифф | задачу читает исполнитель командой `show`, ты — только отчёт |
| После `/clear` задача переделана заново | в журнале нет строки `готово` с хешем | писать строку в момент проверки коммита |
